## Part A — The L1 Platform (CA PracticeOS Compliance)

### A0. Dashboard
Sidebar → **▦ Dashboard**.
- KPI tiles: Clients, Documents, UDIN Pending, Net Worth Drafts — all live counts from local browser storage.
- "Firm Setup — Make CA PracticeOS Yours" card: any CA firm can white-label this by uploading its own firm profile and client master; everything downstream (letters, certificates, checklists, registers) uses that data automatically.
- "Quick Create" buttons jump straight into Engagement Letter, Net Worth, Certificate, Representation, or Working Paper.
- "Professional Control Reminder" notice: explicitly states this is a drafting/workflow assistant — final professional responsibility stays with the signing CA. Worth reading on camera; it sets the tone for the whole app's honesty about scope.
- "Recent Documents" — last 5 items from the Document Register with status badges.

### A1. Client Master
Sidebar → **◉ Client Master**.
- Bulk upload via CSV/Excel ("Upload / Update Client Master"), matched to existing records by PAN → GSTIN → exact name; unmatched rows are added as new clients.
- **Dynamic columns supported**: any extra columns in your file are retained as Custom Fields without needing code changes.
- "Download Template" gives the exact CSV shape expected.
- This is the table Agent 1 (Onboarding) in the L2 layer writes into — show a CSV generated by Agent 1 landing here via this exact same import flow.

### A2. Securities / ISIN Master *(new)*
Sidebar → **◆ Securities / ISIN Master**.
- Bulk upload of share/mutual fund/bond/debenture holdings (Client PAN, Security Name, ISIN, Type, Quantity, Current Value), matched to a Client Master record by PAN then name.
- Feeds directly into the Net Worth Certificate generator via "Load from Securities / ISIN Master" — pulls a client's holdings straight into the Assets table instead of typing them in by hand.

### A3. Document Register
Sidebar → **▤ Document Register**.
- Every document generated anywhere in the app lands here with a status: Draft → Submitted for Approval → Approved/Returned for Changes → Issued/Superseded.
- This is the spine the maker-checker approval workflow runs on (see A16, Security & DPDP has the full explanation — also see the standalone answer already given on how controls work in this app).

### A4. Engagement Letter Generator
Sidebar → **✎ Engagement Letter**.
- 10 assignment types (Statutory Audit, Tax Audit, Internal Audit, GST/Tax Consultancy, Accounting Services, Certification Assignment, Net Worth Certificate, Bank Finance/CMA, Due Diligence, Other).
- Built-in GST engine computes CGST/SGST/IGST based on supplier state, place of supply, and rendered-state, rather than a flat guess.
- Generates a formatted draft with firm letterhead, scope, responsibilities, fees, confidentiality, and acceptance sections.

### A5. Net Worth Certificate Generator
Sidebar → **₹ Net Worth Certificate**.
- Asset/liability line items with evidence/basis per row; "Load Typical Items" seeds common categories; "Load from Securities / ISIN Master" pulls real holdings in.
- Auto-computes total assets, total liabilities, net worth, and net worth in words.
- UDIN and Membership Number fields on the final draft (even if left blank/pending).

### A6. Certificate Generator
Sidebar → **✓ Certificate Generator**.
- 10 certificate types (Turnover, Capital Contribution, Utilisation, Solvency, Stock, Debtors, Creditors, Financial Position, Balance Confirmation, Other).
- Same GST-aware fee handling as the Engagement Letter.

### A7. Representation Letter
Sidebar → **▭ Representation Letter**.
- Client-side representation letter tied to a specific assignment/period, with an explicit client responsibility-acknowledgement clause.

### A8. Working Paper
Sidebar → **▥ Working Paper**.
- Objective, procedures performed, evidence/exceptions, conclusion, and a Prepared By / Reviewed By sign-off row — the standard audit working-paper shape.

### A9. Checklists
Sidebar → **☑ Checklists**.
- Six procedural checklists (Net Worth Certificate, Statutory Audit, Tax Audit, General Certificate, Bank Finance/CMA, GST Assignment) — these are **workflow/process checklists** ("bank statements obtained," "client representation obtained"), a deliberately different thing from Agent 3's **clause-presence** checklists in the L2 layer. Worth explicitly distinguishing the two on camera if you cover both.

### A10. UDIN Register
Sidebar → **◈ UDIN Register**.
- Internal tracking only — explicitly does not generate or validate a UDIN with ICAI. Bulk upload/update by UDIN or certificate number.

### A11. Professional Fees & GST
Sidebar → **₹ Professional Fees & GST**.
- Fee calculator with GST split, advance received, and balance due; generates a fee note draft and maintains a running Fee Register.

### A12. GST Tax Engine
Sidebar → **▤ GST Tax Engine**.
- The centralized GST decision logic reused across fee notes, engagement letters, certificates, and reconciliation: supplier state, legal place of supply, actual rendered/delivered state, SEZ special-case handling (SEZ status is sourced from Client Master, not inferred from GSTIN alone), and an explicit override with "review required" flagging.

### A13. Document Vault
Sidebar → **🗂 Document Vault**.
- Upload signed letters/reports/financial statements/deeds against a client and assignment, with a register showing file hash and status.

### A14. Version Control & Document History
Sidebar → **↺** (under Documents).
- "Never overwrite an issued professional document" — every revision is a new version with timestamp, author, and reason; the original is preserved.

### A15. Contracts & Deeds
Sidebar → **📜 Contracts & Deeds**.
- Metadata register for service agreements, engagement agreements, loan agreements, partnership/LLP/trust deeds, leases, vendor contracts — with renewal dates and review status.

### A16. Digital Signatures / eSign Centre
Sidebar → **✍ Digital Signatures**.
- Explains the real DSC signing chain (hash → sign with token/eSign → embed signature+certificate → recipient validates). Explicitly states: **CA PracticeOS should never store a DSC private key** — this prototype only records signing metadata and document hashes, never the key itself. A genuinely honest security boundary worth calling out on camera.

### A17. Integrations
Sidebar → **🔗 Integrations**.
- OneDrive/SharePoint (via Microsoft Graph, OAuth — prototype stores settings, not credentials), Computex/accounting software (API or controlled CSV import/export), Zoho — all explicitly scoped as "credentials belong in the production backend, not this HTML file."

### A18. Reconciliation
Sidebar → **⇄ Reconciliation**.
- Compare books against an external source, quantify differences, document follow-up before a report/certificate is finalized.

### A19. Firm Setup Wizard
Sidebar → **★ Firm Setup Wizard**.
- Step-by-step: upload firm profile → upload Client Master → configure Firm Access Control & Approval Workflow (Admin/Preparer/Approver names and emails — the maker-checker setup).

### A20. Security & DPDP Centre
Sidebar → **🔐 Security & DPDP**.
- RBAC roles, MFA policy selector, auto-lock timer + manual lock, audit trail (every meaningful action across the whole app is logged here, exportable as JSON), DPDP registers (data inventory, data-principal requests, incidents), and a 12-item "Production Security Checklist" that's honest about what's still backend-only (server-side MFA/RBAC, tenant isolation, encryption, WAF, pen testing).
- **This is the best section to demonstrate the app's honesty about scope** — it doesn't claim production-grade security; it lists exactly what's missing.

### A21. Settings
Sidebar → **⚙ Settings**.
- Firm profile fields (name, CA/partner name, membership, FRN, address, contact, GST state) that flow into every generated document's letterhead and footer.

## Part B — The L2 AI Agent Layer (Streamlit)

*(Full detail already in [VIDEO_SCRIPT.md](VIDEO_SCRIPT.md) — summarized here for continuity with Part A.)*

### B0. Dashboard
Sidebar-nav landing page: KPI tiles (3 agents, 6 document types, 1 connector, headline = Compliance), Quick Jump buttons, and a one-line description of each piece — deliberately mirrors the L1 Dashboard's layout and tone.

### B1. Agent 1 — Onboarding
Photo/PDF of a PAN card or GST certificate → validated Client Master row → CSV that imports directly into **A1 (Client Master)** above. Demo the actual import to close the loop.

### B2. Agent 3 — Compliance (the headline feature)
Paste a drafted document → perceive → reason → self-check → act → PASS/FAIL with exact missing clauses and evidence quotes. This is explicitly a *different* kind of checklist from **A9 (Checklists)** — A9 checks whether procedural steps were done; Agent 3 checks whether the document's actual text contains the required clauses.

### B3. Agent 2 → Agent 3 — Drafting + Compliance
One plain-English line → a filled draft (reusing L1's document structure) → immediately compliance-checked. The strongest demo beat: the engagement letter draft genuinely fails on a missing Limitations clause, because that clause was never in L1's own template — Agent 3 catching a real gap, not a rigged one.

### B4. Tally Connector
Pulls client/ledger/invoice data via ICAI's Tally Prime MCP Server when running locally alongside Tally; otherwise an honest cached-data fallback, clearly tagged `"source": "live"` vs `"cached_fallback"`.
